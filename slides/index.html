Scenarios

Adding scenarios to our app


A common use for a DES app is to compare scenarios with different inputs.

Our current app shows results for one run at a time. Changing the inputs and running again replaces the previous results.

To compare scenarios, we need to:

  1. Save each run’s inputs and results.
  2. Allow users to view and compare saved scenarios.

Two pages: run scenarios and explore results

As shown, our app now splits the original simulation page into two:

  • Run simulation: set inputs and run the model.
  • View results: view results from a saved scenario or compare several.


Why?

These pages support two different tasks: setting up simulations and making sense of their results. Users can move between them without having to do both in the same place.

This keeps the interface manageable if we add more inputs, results and comparison features.

New dictionary in session state

We first create an empty dictionary in session state, ready to store scenario results.

st.session_state.scenarios = {}


We need to make sure it is only created it if it doesn’t already exist.

This is because Streamlit reruns the script when users interact with the app. Without this check, each rerun would replace the dictionary with an empty one, clearing any saved results.

if "scenarios" not in st.session_state:
    st.session_state.scenarios = {}

New dictionary in session state

We’ll initialise the dictionary in app.py, which runs before whichever page the user opens.


Why not in simulation.py?

Users might open the results page before running a simulation. If we created the dictionary only in simulation.py, it wouldn’t exist yet, causing an error.

Putting this code in app.py ensures the dictionary exists before either page needs it.

"""Entrypoint for app. Defines navigation."""

import streamlit as st

# Initialise session state before running any page
if "scenarios" not in st.session_state:
    st.session_state.scenarios = {}

style_settings()

We’ll write this function near the start of our results.py script.

It checks each row’s scenario name against chosen_scenarios. Matching rows get a pale blue background. We use .style.apply() to apply this formatting row by row, then .format(precision=2) to display decimal values to two decimal places.

# Function for highlighting the row/s with the chosen scenario/s
def style_settings(settings, chosen_scenarios):
    def highlight(row):
        style = (
            "background-color: #dbeafe; color: #111827"
            if row["Scenario"] in chosen_scenarios
            else ""
        )
        return [style] * len(row)

    return settings.style.apply(highlight, axis=1).format(precision=2)

Hosting with stlite

Reminder: Streamlit Community Cloud

In the last session, we introduced Streamlit Community Cloud.

It was an easy way to deploy from GitHub, with automatic updates when you push changes.

However, apps share limited server resources and go to sleep after 12 hours without visitors.

stlite

An alternative is stlite, which runs Python directly in the user’s browser. Instead of sending requests to a server to run your code, the user’s own device does the work.

Pros:

  • Host for free with GitHub Pages.
  • No server to wake up.
  • No external resource limits.

Cons:

  • Initial loading can take longer while Python and packages download.
  • Performance depends on the user’s device.
  • Not all Python packages and Streamlit features are supported.
  • Set-up is not as easy as Streamlit Community Cloud.
  • Browser caching can leave users seeing an older version of the app.

Running a Streamlit app with stlite

To use stlite, we add an index.html file to our app folder. HTML defines the structure and content of a web page. This file loads stlite and tells it how to launch our app.


We can reuse a standard template, changing a few details for our app.

Let’s work through the index.html used to deploy the scenario app.

<!doctype html>
<html>
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1, shrink-to-fit=no" />
    <title>Scenario app</title>
    <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@stlite/browser@1.12.2/build/stlite.css" />
    <script type="module" src="https://cdn.jsdelivr.net/npm/@stlite/browser@1.12.2/build/stlite.js"></script>
  </head>
  <body>
    <streamlit-app src="./app.py">
        <app-file name="home.py" url="./home.py"></app-file>
        <app-file name="model.py" url="./model.py"></app-file>
        <app-file name="results.py" url="./results.py"></app-file>
        <app-file name="simulation.py" url="./simulation.py"></app-file>
        <app-file
            name="images/model_diagram.drawio.png"
            url="./images/model_diagram.drawio.png"
        ></app-file>
        <app-requirements>
            simpy==4.1.2
            numpy
            pandas
            sim-tools==1.3.0
        </app-requirements>
    </streamlit-app>
  </body>
</html>
